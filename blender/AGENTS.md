# blender — AGENTS

Blender stage of golf-map → OPCD → GSPro: bunker tooling run on the OPCD course `.blend` (after SVG
import and conform) and the paint conventions shared with Unity. Not part of the build.
[README.md](README.md) = what exists and how to run it. [RESEARCH.md](RESEARCH.md) = OPCD/Afrod vs
Bunker Studio, ce.simgolf's method, the lip-tool plan, Vreta findings. Read both before bunker work.

## Layout

Also read by `unity/Editor/GolfMap/GolfMapBunkerChannels.cs`; copy to `Assets/GolfMap/<Course>/` after an edit. |
| `tools/fbx_sync.py` (+ `fbx_sync_test.py`) | Add-on + headless: export only changed meshes to the FBX folder (OPCD names/settings, fingerprints in `<folder>/.golfmap-fbx-sync.json`). Unity counterpart: `golfmap.meshes.sync`. |
| `tools/bunker_paint_report.py` | Headless report: which convention each bunker/blend is painted with. Same rings and scores as Unity's **Check paint**. |
| `tools/shape_prepare.py` | Headless shaping step 2 ([SHAPING-PLAN.md](SHAPING-PLAN.md)): fresh OPCD `.blend` → OPCD's Import Terrain OBJ + Conform to Terrain → `<name>.conformed.blend` (never saves the source) + report. Per-mesh conform cache in `<blend folder>/shaping-staging/conform-cache/` keyed on the mesh's pre-conform state + modifier stack, the terrain's content hash and the state of every conform target (`Outer`, `Terrain`): a regenerated `.blend` conforms only what changed; writes `<name>.conformed.terrain.json` so the worker notices a regenerated terrain.obj (README "The per-mesh conform cache"). `--conform grid` (`GOLFMAP_PREPARE_GRID_CONFORM=1`) computes the projection as a cell lookup on the terrain's own grid instead of a Shrinkwrap — the conform compute 138 s → 1.2 s, agreeing to 38 µm; the operator path is still the default (README "The grid conform path"). |
| `tools/shape_carry.py` (+ `shape_carry_test.py`) | Run by shape_prepare before the conform: the previous OPCD build's source mesh put back for every mesh whose SVG shape is unchanged (the export's `<stem>-shapes.json` fingerprints), the same topology with every vertex within 5 mm or the same border (OPCD re-fills outlines); a kept neighbour's shared border vertices welded to it so no seam opens; seams between kept meshes snapped back to the old vertices (<= 5 mm), and every kept plain mesh OPCD refilled patched with the old faces that still fit (`tools/shape_patch.py`, CDT for the gaps; `GOLFMAP_CARRY_PATCH=0`). Keeps the conform and op caches warm across OPCD builds. State in `shaping-staging/carry-over/`; `--no-carry-over`. README "Carry-over from the previous build", "The patch". |
| `tools/shape_prepare_cache_test.py`, `tools/shape_worker_stale_test.py` | Headless tests: the conform cache on a synthetic course (what the key covers, what a hit restores) and `shape_worker.conformed_stale` against the source `.blend` and terrain.obj's content sha. |
| `tools/shape_coords.py` | EPSG:3006 ↔ `.blend` x/y/z from the inner DEM sidecar (pure Python, self-test). |
| `tools/terrain_obj.py` (+ `terrain_obj_test.py`) | `terrain.obj` from the exported `.raw` + sidecar, equal to Unity's Terrain › Export To OBJ (half resolution, same frame; pure Python + numpy, run with the pipeline venv). README "terrain.obj without Unity". |
| `tools/shape_apply.py` | Headless shaping step 3: replays `docs/gspro/<course>/shaping/NN-*.json` on the conformed cache (Afrod ops driven like the UI, seeded per feature; `golfmap.flatten_footprint` with protected play surfaces; `golfmap.weld_tjunctions`, automatic after `afrod.cutcartpaths` (after the cut's slivers are collapsed, `sliverM`), then the cut's paint restored or kept as crisp joints per path surface; `golfmap.split_surfaces` cutting a mixed-surface road into one object per surface; `golfmap.cut_out` lifting an EPSG:3006 outline (a rock slab) out of the meshes under it as its own `Spline_<name>_Rock_-_Mesh`, README "Shaping: cut-outs"; composite recipes through shape_studios) → `shaping-report.json` (per-op moves by type, warnings, seams/T-junctions, `changedPlaces` per op unit for Unity's Review) + changed FBX into a staging folder. Holds the headless/determinism shims for Afrod and Edit Mesh Tools, the exact speed shims (knife cut, paint, smooth ripple), the op units (`plan_units`: reads per feature group) and the op-result cache (`<blend folder>/shaping-staging/cache`, keyed on op + unit + input mesh state hashes; README "Shaping: apply"). Never saves the `.blend`. |
| `tools/shape_region.py` (+ `shape_region_test.py`) | Pure numpy: the op cache's region entries - a unit with a `region` (cut-outs, tee flattens) keyed on the K part of each mesh around it, the piece it leaves, the transplant onto another build's mesh, `canonical_hash` (order-free). Test (synthetic builds, patch + region hit = cold compute): `blender.exe -b --factory-startup --python-exit-code 1 --python blender/tools/shape_region_test.py`. README "Region entries". |

## Rules

- **Never save the course `.blend` from a script.** Report only; geometry edits go on a copy or are run by the user in the UI.
- **Python 3.11:** no nested same-type quotes in f-strings, no `type` statements. Test headless before claiming a script works.
- **Pairing:** OPCD metadata first (`opcd_parent_id`, `opcd_kind` = `mesh`/`blend`); names as fallback (`<key>_Bunker_-_Mesh`, blends start with `<key>_`, incl. split `<key>_piece1_Rough_B_Bunker_-_Blend`). Unity only has names.
- **Paint colour** = dominant channel; black when max(r,g,b) < 0.25. Same rule in Unity — change both together.
- **Shaping ops must be exact and declare their reach.** A new op type needs a `PLANNERS` entry whose `reads` cover every mesh it can read or move (the op cache keys on them, the worker restores and re-runs by them); an op that moves a mesh outside them is reported as an `escape`. A planner that sets `unit.region` promises the unit changes nothing outside that box; what it does there anyway (a weld far along a border) only costs it its region entry (`cache.regionNotLocal` says why). A speed shim must leave the positions, colour and FBX-fingerprint hashes of a full Vreta apply unchanged (compare with `GOLFMAP_SHAPE_NO_FAST_SHIMS=1`). An op kind keys on the code it runs (`shape_opkey.py`: its `RUNNERS`/`PLANNERS` entry, what that reaches in `shape_apply.py` and sibling modules, plus the cache framework), so an edit invalidates only the kinds that reach it (`python blender/tools/shape_opkey.py` lists them); recipe units also key on `shape_paint.py`, `shape_recipes.py`, the library and, with a studio step, `shape_studios.py`, the Bunker/Shoreline Studio sources and the SVG's greens.
- OPCD Unity model: each mesh has a `MeshChannelMaterialsStore` → `ChannelMaterials` (render material + per paint channel a source material/channel; MAHS shader keeps channels under `_Red*`/`_Green*`/`_Blue*`/`_Black*`). Never edit OPCD's original materials; build copies (Unity `GolfMap > Bunker Materials`).
