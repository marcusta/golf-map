Golf Intel · component treatment guide · closing the feel gap

The tokens landed. The craft didn't — yet.

The build uses the right colours, but the feel lives in how components are made — glass over the map, mono numerics, soft elevation, breathing room. Each section below rebuilds one of your real components to spec, with the exact CSS beside it. Copy the recipes; don't re-pick the colours.

What's fighting the vision
01
Opaque panels, not glass

Foundations · layout laws (read first)

General, not per-panel

The truncation and cramping aren't panel bugs — they're the absence of shared layout rules. State these seven once and every overlay obeys them; a new panel just picks a width bucket and decides which controls are contextual. The treatments further down are only these laws applied.

01Hug content
Width from a 3-bucket scale (280 / 340 / 400), height from content. Long lists scroll inside; a panel is never full-height.
02Corner-inset contract
Everything floats at one inset (space-5) from the viewport edge. Overlays sharing a corner share that edge + a space-3 gap.
03Space carries structure
One interior padding (space-4), one row gap (space-2). No per-row hairlines — dividers only between major groups.
04Disclosure on demand
Row affordances (eye, drag, delete) reveal on hover; edit/reorder appear on selection. Nothing secondary holds permanent width.
05Text beats chrome
Labels never truncate; columns size to content. Numbers sit in a fixed mono-tabular right column. If space is tight, chrome yields — not the label.
06One primary · tiered depth
One clay action per surface. Elevation is tiered from tokens — map < panel < popover — never ad-hoc shadows.
01 · Floating panels → glass

Chrome floats over terrain, it doesn't cover it

Layout, not tokens

The first pass applied these recipes but inherited the old information architecture — a fixed narrow dock, a two-column grid with a permanent eye per row, full-height panels. That's why labels truncate to “Bun…” and “Yello…”. The fixes are structural, not token-level:

· Roomier grid / wider dock so labels never truncate
· Eye reveals on row hover — reserves zero permanent width
· Panels hug their content, not the viewport height
· No per-row hairlines — spacing + hover tint carry structure
· Order controls are contextual — appear only on selection
· Toolbar + dock share one corner inset & left edge

Rules
  • Any figure a user reads as a measurement → --font-mono + tabular-nums.
  • Units (m, y, pts, mph) drop to text-tertiary and ~80% size — the number leads.
  • Right-align numeric columns so they scan vertically.
  • Big readouts use metric-xl; deltas use --data-good/bad.
  • Labels like PAR, PLAYS LIKE → mono overline, uppercase.
.metric {
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums;
  font-weight: 600;
}
.metric__unit {
  color: var(--color-text-tertiary);
  font-size: 0.8em;
  font-weight: 400;
}
.metric-col { text-align: right; }

Rules
  • Never set raw text on the map. Wrap it: a dark --overlay-readout-fill pill or a scrim behind.
  • Distance labels = mono tabular pills, one per leg — never let two overlap; collision-nudge or hide at zoom.
  • Hole markers: surface-brand (pine) circle, bone number, 2px bone ring for contrast on any turf. Green/tee markers may take the feature colour.
  • Over-map text colour is always --overlay-text (white) on the scrim, not a theme text token.
.map-label {
  background: var(--overlay-readout-fill);
  backdrop-filter: blur(8px);
  border-radius: var(--radius-pill);
  padding: 6px 12px;
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums;
  color: var(--overlay-text);
}
.map-marker {
  background: var(--color-surface-brand);
  border: 2px solid var(--overlay-text);
  border-radius: var(--radius-pill);
}

Rules
  • Exactly one clay primary per view. Secondary = surface-raised + border; tertiary = ghost; danger = status-negative tint.
  • Tool switcher is a segmented control, not four loose buttons — active pill lifts on surface-raised with a clay icon.
  • Kill native <select>/<input> chrome: surface-raised fill, border-default, radius sm, focus = border-focus + 3px clay glow.
  • Numeric inputs use mono + a muted unit suffix.
.btn-primary {
  background: var(--color-accent-primary);
  color: var(--color-on-accent);
  border: none; border-radius: var(--radius-sm);
  padding: var(--space-3) var(--space-4);
  transition: background var(--dur-fast) var(--ease-standard);
}
.btn-primary:hover { background: var(--color-accent-hover); }

.field:focus-within {

06 · Iconography

One monoline set, one weight

Replace the emoji flag and mixed glyphs with a single monoline set — Lucide or Phosphor (line) both match the language. Ship it as the icon primitive on both platforms.

  • Stroke 1.75px, round caps & joins.
  • Size on the 4-pt grid: 16 / 20 / 24.
  • Colour inherits currentColor — never hard-coded.
  • The wordmark flag becomes a simple line mark, not an emoji.

Do these first — biggest feel-per-hour
  1. Glass-ify the two map panels. Translucent fill + blur + soft elevation. Single biggest shift.
  2. Put every number in JetBrains Mono tabular. Global find: stat, distance, par, count, coordinate.
  3. Wrap all over-map text in scrim pills and stop the label overlaps.
  4. Add spacing rhythm — replace ad-hoc padding with the --space-* scale; give panels room.
  5. Style form controls + segment the toolbar.
  6. Swap in one monoline icon set.

1–3 alone will move the product most of the way to the vision. Everything here reads straight from the tokens you already shipped in tokens.css / Tokens.swift — this is application, not new decisions.
