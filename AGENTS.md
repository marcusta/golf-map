# golf-map — AGENTS

Golf course map system. Server is the source of truth; web builds courses and plans strategy; iOS is on-course GPS (in progress). **Current focus: building courses in the app and taking them into OPCD/GSPro (Blender + Unity).** Architecture and phases: [ROADMAP.md](./ROADMAP.md).

## Areas (read the area's AGENTS.md before working in it)

| Dir | Stack | Role |
|-----|-------|------|
| [server/](server/AGENTS.md) | Bun + Hono + Kysely + SQLite, `@basics/core` | Course data, map-build jobs, GSPro export, tiles. `builder` mode (local, runs the pipeline) vs serve mode (VPS). |
| [web/](web/AGENTS.md) | Vite + TS, MapLibre | Create mode (map build, drawing, zones, export panel), strategy planner, analytics. |
| [pipeline/](pipeline/AGENTS.md) | Python venv, rasterio | `golfpipe`: Lantmäteriet lidar/ortho → DEM + tile pyramids, tree/zone/building detection. `gspro.py`: GSPro export files. |
| [unity/](unity/AGENTS.md) | C# 6, Unity 2018.2 editor scripts | Terrain importer, tree/building planters (VSP), zone importer, bunker materials. Edited here, **synced into** the Unity project with the `unity` MCP server (`unity/mcp/`), which also drives the open editor. |
| [blender/](blender/AGENTS.md) | Python (`bpy`, Blender 4.5) | Bunker paint conventions + tools on the OPCD `.blend`. |
| [ios/](ios/AGENTS.md) | SwiftUI, MapLibre, GRDB | On-course GPS. No course building. |
| `shared/` | TS | `api/*.gen.ts` (generated — never hand-edit), `strategy/`, `render/`, `vegetation/` (tree model ids and the model library). |

## Course → GSPro chain

| Stage | Where | Output |
|---|---|---|
| 1. Map build (area → lidar DEM, ortho, tiles) | web Create mode → `MapBuildService` → `golfpipe` | `data/tiles/<siteId>/`, `data/sources/<siteId>/` |
| 2. Draw features, terrain edits, vegetation zones; Regenerate trees | web `draw/`, `terrain-edit/`, `zones/` | `data/app.sqlite` |
| 3. **Update \<target\>** — one verb per thing the course is made of | the GSPro board (web `export/`) or the command bar → `GsproSyncService` → `GsproExportService` / `ShapingService` → `gspro.py` + the push into the open Unity editor ([docs/gspro/export.md](docs/gspro/export.md)) | that target's whole chain, run and reported as one job: terrain, photo, shapes, meshes, vegetation, trees, buildings, props (the spec, the Blender models, the place that keeps hand moves), creeks, waterfalls, course file. The board carries each row's last run, what changed since, stale/blocked, the row's own note and the manual step left |
| 4. SVG → Blender | **the one manual gate**: build the SVG into meshes with the OPCD add-on. The rest is automated — `terrain.obj` from the exported heightmap and Conform to Terrain (`shape_prepare.py`), then the shaping replay ([blender/README.md](blender/README.md)) | course `.blend` → the changed FBX |
| 5. Assemble in Unity | `unity_command golfmap.course.refresh {save: true}`: meshes.sync, bunker/path materials, paint, rough grass, terrain conform, water planes, creeks, walls, surfaces.export, then the scene saved | GSPro course |
| 6. Vegetation through Arborist (trees and lower vegetation; grass stays in VSP) | command bar **Update vegetation** (Unity planting, then `ArboristService` → `pipeline/arborist.py`), or `bun run arborist -- <course>` for the file plus a reload in the running Arborist; its mod (`unity/ArboristMod/`) for judging looks — start at [docs/gspro/arborist.md](docs/gspro/arborist.md) | `arboristdata.dat` in the GSPro course folder |

## Conventions

- Bun workspaces `server`, `web`, `shared`: package scripts run with **cwd = the package dir**; root scripts (`start`, `dev`, `start:vps`, `db:migrate`, `db:health`) with cwd = repo root. `bun run dev` (`scripts/dev.ts`) is local development: `start`'s server under `bun --watch` (restarts on any server/shared change; in-memory export/build jobs die with it) plus the web Vite dev server proxying to it; `PORT` = server (3000), `WEB_PORT` = Vite (5173). `start:vps` carries the whole serve-mode environment (pinned by `scripts/vps-start.test.ts` against `deploy.json`); change port/DB paths there, never in the systemd unit.
- `@basics/core` is a vendored tarball (`vendor/basics-core-<X.Y.Z>.tgz`) declared by all four package.json files. Upgrade only with `bun run fw:update [X.Y.Z]` (needs sibling `../mackans-client-fw`), then commit tarball + package.jsons + `bun.lock` together. Never edit `node_modules/@basics/core`, the tarball or the dep strings; fix the framework upstream and release it (`bun release.ts <level>`, needs a `CHANGELOG.md` heading).
- `bun link @basics/core` for live framework work; **never commit while linked** (the local guard `scripts/assert-not-linked.ts` — `bun run fw:check` — runs before every `test` script, so `bun run test` works without the sibling repo; don't bypass). Restart Vite after link/unlink/update; `rm -rf web/node_modules/.vite` if exports look stale.
- API: change `server/api/*.api.ts`, then `bun run generate` (cwd `server/`).
- Styling: only core's `s` spacing scale is used — see [web/AGENTS.md](web/AGENTS.md).
- `data/` (gitignored): `app.sqlite`, `sessions.sqlite`, `obs.sqlite`, `tiles/`, `sources/`.
- Auth: cookie sessions; no signup — `create-user` CLI. Tile routes are public.
- `docs/`: feature proposals and decisions (`decisions-*.md`, `feature-*.md`); read the relevant one before touching the planner/strategy layer or a feature it covers.
- Language: everything in the repo is English — code, identifiers, comments, commit messages, docs, skills. Chat with Marcus is in Swedish. He describes terrain, groundwork and vegetation in Swedish (`stenröse`, `berghäll`, `slänt`); when such a term maps to an English one used in code or tools (fringe, rough, cut-out), give both the first time, and ask when unsure what a Swedish term refers to on the ground.
- Photo cleanup — removing trees, shadows, players and paths from the ortho photo before it goes onto the Unity meshes, and how to draw the cleanup areas: [docs/photo-cleanup.md](docs/photo-cleanup.md).
- Cross-area workflows (terrain round-trip and order of operations, new vegetation zone → Unity, Unity script edit + sync, re-placing props/walls without losing hand edits, editing the cleaned ortho photo in an image editor, a rock slab / berghäll in the ground, stepped ponds and waterfalls, a creek's edge showing on a pond): [docs/workflows.md](docs/workflows.md) — read before any of them.

## This machine (Windows 11, native, no WSL)

- GSPro exports without the web panel: `bun run gspro:export -- status <course>` / `-- <course> <kind[:terrain]>...` (`scripts/gspro-export.ts`, same service as the panel). Kind `arborist` writes the course's Arborist file (`--arborist-out <folder>` for a trial that leaves the GSPro course folder alone).
- What is out of date in GSPro, per target (terrain, photo, shapes, meshes, vegetation, trees, buildings, props, creeks, waterfalls, course file): `bun run gspro:status -- <course>` prints the status board (last updated / what changed since / stale / blocked / the row's note / the manual step) plus the open Unity editors; `bun run gspro:update -- <course> <target|stale>` runs that target's whole chain — both terrains, the files and the push into the open Unity editor — printing each phase (`GsproSyncService`, [docs/gspro/export.md](docs/gspro/export.md) "The GSPro status board"; exit 1 on failure).
- The Blender shaping loop without the web Terrain editor: `bun run shaping -- <course> [--dry-run]` (`scripts/shaping-apply.ts`, same `ShapingService.apply`: regenerates the layer files, drives the Blender worker, refreshes the changed objects in Unity; a changed rock slab also gets the surface map exported and the vegetation planted). Prints each phase, the changed objects, warnings and Unity steps; exit 1 on failure.
- Vertex paint of the course meshes (hand-paint strokes and paint rules in `docs/gspro/<course>/paint.json`, painted by Blender's `golfmap.paint` ops): `bun run paint -- <course> list | stroke --line|--polygon e,n e,n ... | --circle e,n --radius R --channel red|green|blue|black [--width W] [--feather F] [--strength S] [--mode replace|overlay] [--surfaces Rough,Deep] [--id ID] | rule set <json> | rule disable <id> | remove <id> [--dry-run] [--sync]` (`scripts/paint.ts`, the same `PaintService` as the Terrain editor's Paint tool): a temporary preview in the open Unity editor first (until the mesh's next FBX), then paint.json and the paint layer (`PAINT_LAYER_LIVE` in paint.service.ts gates the layer write); `--sync` runs the shaping apply.
- Is the built course whole (gaps, seams, cracks, steps, colliders, upside-down faces) before a course build: `bun run course:check -- <course> [--hole N] [--buffer 100] [--no-blender] [--json]` (`scripts/course-check.ts`, `CourseCheckService`, the board's Course › Check row): writes `<prefix>-play-lines.json` (every tee -> aim points -> green of every course on the site; `gspro.py play-lines`), runs Unity's `golfmap.course.check` on the play-surface meshes those lines cross + 100 m (a course without holes: the drawn `oob` ring + 50 m), opens the findings in GolfMap › Review, then the shaping worker's `/check` when it holds the course. Exit 1 on errors, 2 when Unity could not run. What each finding means: unity/README.md "Course check".
- Make ready before a GSPro build (every object within 40 m of play has a GSPro collider with the right GSP* material, plus faults): `bun run course:ready -- <course> [--fix] [--margin 40] [--json]` (`scripts/make-ready.ts`, `MakeReadyService`, the board's Course › Ready row): Unity's `golfmap.course.ready` (`--fix` adds what is missing and saves the scene; `<export dir>/make-ready.json`), the Arborist trees/bushes near play in `arboristdata.dat` (report only), the course check folded in; summary in `<export dir>/make-ready-summary.json`. Exit 0 ready, 1 not ready, 2 failed or Unity closed.
- How far a course has come on its way to GSPro, as one checklist (set-up, map, cleaned photo, the board's rows with the OPCD build after Shapes, Check, Ready, the GSPro build, the GreenKeeper score): `bun run course:progress -- <course>...|all [--json]` (`scripts/course-progress.ts`, `CourseProgressService`; reads only, ~5 s a course). Marcus's Claude status pane reads its `--json`, so keep that shape.
- What the vegetation is planted by: `bun run vegetation:rules -- <course> [--only <source>] [--json]` prints every generator's and the tree chain's rules with the course's own values marked (the Vegetation mode's **Planting rules** panel shows the same). The rules are config in `pipeline/vegetation-rules/*.json`; a course overrides any of them in `docs/gspro/<course>/vegetation-rules.json` ([pipeline/AGENTS.md](pipeline/AGENTS.md) "Vegetation rules").
- Young trees on open ground the lidar missed (photo stems, found from their shadows in the summer photo): `bun run trees:photo -- <course> [--dry-run] [--accept <id,...>|all] [--skip <id,...>]` (`scripts/trees-photo.ts`, the same `PhotoStemsService` as the Vegetation mode's **Trees in photo…**); accepted ones are planted by the trees export with `src: "photo"` ([pipeline/AGENTS.md](pipeline/AGENTS.md) Notes).
- Shapes drawn before the holes (all in Others) onto their holes: `bun run holes:assign -- <course> propose [--all] | accept [<featureNo|id>,...] [--dry-run]` (`scripts/holes-assign.ts`, the same `HoleAssignmentService` as the Draw stack panel's **Assign to holes…**): greens/tees by the hole's green centre/tee points, the rest by a vote along each hole's play line (back tee → aim points → green); every hole on the course's site takes part (a sibling course's shapes are named, left alone); ordinary roughs go into Roughs; accept keeps the Others order. The rules: `shared/features/hole-assignment.ts`.
- The course file's hazard lines (a line staked round each water no drawn penalty line holds, the drawn penalty lines, the inner OOB) and their noAIL: `bun run gkd:lines -- <course> [list] [--json] | adopt <water,...> [--type penalty_red|penalty_yellow] [--dry-run] | ail <feature,...> on|off [--dry-run]` (`scripts/gkd-lines.ts`, the same `GsproExportService.gkdLines` and spline fit (`web/src/geo/hazard-line-fit.ts`) as Furniture › Rules lines' **Edit line** and **Play as it lies**): adopt turns the automatic line holding exactly those waters into a drawn penalty line on their shared hole; `ail on` = played as it lies (the default), `off` = `noAsItLies: true`. The first run after a change takes 6-8 s (`gspro.py gkd-lines`).
- Will the creeks come out deep enough in the course meshes (terrain.obj's 1 m grid, OPCD's smooth and ~1.2 m triangles fill narrow channels in): `bun run water:depth -- <course> [--feature <id or start>[,...]] [--json]` (`scripts/water-depth.ts`, the same `GsproExportService.creekDepth` → `gspro.py creek-depth` as the Terrain editor's **Depth** button beside Dig creeks): per creek ok / shallow (first stretch at x,y EPSG:3006) / not-dug / stale / off / on-lake, measured on `dem-edited.tif`, or on the raw DEM with the site's edits replayed while some are not applied. ~5 s, writes nothing. Exit 0 all fine, 1 any shallow/not-dug/stale, 2 failed.
- Will OPCD build the shapes: `bun run svg:check -- <course> [--all] [--json] | accept <key> [--note <why>] | unaccept <key>` (`scripts/svg-check.ts`, the same check as Draw › **Check shapes…**): overlap slivers and necks under OPCD's 0.24 m blend, hidden shapes and greens on rough are errors that stop the SVG export (nothing written) until fixed or accepted in `docs/gspro/<course>/svg-checks.json` ([docs/gspro/export.md](docs/gspro/export.md) "SVG checks").
- A course's tree models (`docs/gspro/<course>/models.json`; the palette refers to them): `bun run models -- add "<course>" arborist:<label> --species <species> [--dry-run]` sizes an Arborist model from `data/arborist/catalog-sizes.json` and refuses a label Arborist lacks; `-- list "<course>"` prints the library. One shared library (`docs/gspro/model-library.json`, `add --shared`, `-- promote "<course>" <model>`) with per-course overrides and course-only models in the course's models.json; the repo's files are the source: Unity's copies are generated (resolved library + palette, `-- sync "<course>" [--dry-run] [--force]`, drift refused with a diff); never hand-edit them in Unity ([docs/gspro/arborist.md](docs/gspro/arborist.md) "Models, placements and tree ids").
- The Arborist vegetation loop in one command: `bun run arborist -- <course> [--trees|--lower] [--no-reload] [--screenshot [<view>...]] [--close-others]` (`scripts/arborist.ts`, the same `ArboristService` as Update vegetation): rewrites the course's `arboristdata.dat`, reloads it in the open Arborist (`ResetVSPro` + `LoadData`, then `veg.systems` polled until the vegetation count stops changing) and takes the screenshots with `fps`/`veg.at`. It never starts Arborist; no bridge gets a diagnosis, not a timeout. [docs/gspro/arborist.md](docs/gspro/arborist.md).
- Who draws each tree, decided before planting (a course with `routing` in its vegetation-rules.json; Omberg): `bun run arborist -- route <course> [--dry-run]` writes `<prefix>-inner-routing.json` (own / billboard / left out by tree id; the trees export and the Arborist edit loop route again by themselves). Unity's planter stores only the vsp models routed own, `arborist.py trees` draws the rest, nothing is trimmed ([docs/gspro/arborist.md](docs/gspro/arborist.md) "Routing before planting").
- One tree or bush Arborist draws (an `arborist:` model), changed live in the open Arborist and saved, **never through Unity**: `bun run arborist -- edit <course> show|move|resize|rotate|delete|swap|add ... (--picked | --pick [u,v] | --near x,z | --id <id>) [--dry-run]` (`scripts/arborist-edit.ts`, `ArboristEditService`): the mod's `veg.edit` first (0.1 s), then `arboristdata.dat`, its ids, the placements and the tree-edits file. `--picked` = the tree Marcus marked in Arborist with the P key ([docs/gspro/arborist.md](docs/gspro/arborist.md) "The edit loop").
- The OPCD cloud build (stage 4, the manual gate) without the browser: `bun run opcd:build -- <course> [--dry-run | --status | --submit-only] [--opcd-name <name>] [--timeout <min>]` (`scripts/opcd-build.ts`) walks OPCD's builder by the words on the page — Menu › Course Workflow › the course's row › Open Dashboard › SVG Jobs — uploads the SVG, waits the build out (2 min, then every 45 s) and saves `<prefix>_svg_<n>.blend` into the export folder; `--setup` records a hand-run into `data/opcd-recording/` when the page has changed. The course is called something else there (`courses.opcd_course_name`, Vreta = "Vreta Kloster golfklubb"). Playwright cannot drive a browser under Bun here, so the script resolves the course in Bun and then re-runs itself under a Node — VS Code's Electron with `ELECTRON_RUN_AS_NODE=1`, since there is no `node` on PATH ([docs/gspro/export.md](docs/gspro/export.md) "OPCD cloud build").
- An OPCD build broke: `bun run opcd:build -- <course> --status` records each export snapshot's outcome in its `export.json` (OPCD's clock = local − 6 h; jobs are named by the snapshot), `bun run gspro:bisect -- <course> snapshots` names the last good one (the sync board's Shapes row shows it too), `... svg-mix [--apply <list>|--without <list>|--match <regex>]` lists/builds variants from the last good and the newest snapshot SVG keyed by `data-feature-id` (`scripts/svg-mix.ts`), and `opcd:build -- <course> --svg <variant> --submit-only` submits up to 3 at once ([docs/gspro/export.md](docs/gspro/export.md) "The fast way when an OPCD build broke").
- A Blender/OPCD build broke after edits, from the database: `bun run gspro:bisect -- <course> changes --from <when>` lists what changed (only feature types the SVG draws), `... svg --from <when> --apply <list>|--without <list>` exports `<course>-bisect-<list>.svg` with just those changes applied, from a copy of the DB. `<when>` = an export snapshot (every full SVG export keeps one in `<export dir>/export-history/`), a local time (edit history, migration 025), `db:<file>` or `now` (`scripts/gspro-bisect.ts`, `FeatureHistoryService`).
- A new course's Unity project (fresh GSPro base unzip): `bun run unity:new-project -- --from <finished project> --to <project> --course <Name>` copies the packages, asset edits, define symbols, scripts and course presets over (`scripts/unity-new-project.ts`, list in `unity/project-template.json`, steps in `unity/mcp/README.md` "New course project").
- No `node` on PATH — use `bun` (also for `unity/*.test.mjs`). Run pipeline Python one way: `bun run py <script> [args]` from the repo root (`scripts/py.ts`: the venv interpreter, cwd `pipeline/`).
- Marcus refers to a YouTube video or playlist: `bun run yt <url>... [--lang sv]` (`scripts/yt-transcript.ts`, needs `yt-dlp`) writes the captions as Markdown with `[m:ss]` marks to `data/youtube/<playlist>/` (single videos: `videos/`). Have cheap subagents read them against the doc that owns the subject, check the claims that matter in the transcript yourself, and put what holds into that doc with `(video NN @ m:ss)` sources. Auto-captions mishear names.
- Write files with the Write/Edit tools; Bash runs commands (27 of 95 sessions had 100+ line `cat <<EOF` heredocs fail with "unexpected EOF").
- Port 3000 is excluded: use preview configs `api-e2e` (3100, isolated e2e DB) + `web-e2e` (5274) from `.claude/launch.json`; login `marcus` / `test-password-123`, course `/course/course-1`.
